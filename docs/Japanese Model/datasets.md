## 最終状態（2026-10-15）

日本語モデル開発は終了し、モデル・SP8000・設定・評価記録を[tts-dataset/pocket-tts-ja-experiments](https://huggingface.co/tts-dataset/pocket-tts-ja-experiments)へpublic/manual gateで保存公開しました。大規模M2aの学習音声はGOL単独で、最終trainは723.507時間・447,090行・327 IDグループ、validは22.329時間・12,951行・106グループです。SP8000の学習テキストは過去のGOL＋MoeSpeech由来であり、学習音声と区別します。

専用Vast.aiインスタンスは削除済みです。大規模GOLの生音声・派生latentsは外部回収しておらず、環境とともに削除されました。HFへ元音声・参照録音・latentsをアップロードしていません。小規模検証のローカル展開物と、大規模M2aデータの保持状況は別です。[現在の状態](index.md)と[保存公開記録](research/2026-10-15-huggingface-archive-publication.md)を参照してください。以下の準備手順・候補・利用状況は実行当時の記録で、追加処理は予定していません。

## 実行当時の使用状況（2026-10-07）

10月のGPU試運転ではGOLとMoeSpeechの小規模subsetを処理し、train 313行・34.06分・3話者ラベル、valid 90行・6.33分・1ラベルで学習しました。これは8月のMoeSpeech 87.1時間のPhase 1とは別runです。**2026-10-07のユーザー指定により、現在のM2aはGOL単独です。** 18作品・選定時1,003.736時間の取得・前処理・alignment・重複/長尺/語彙監査とlatents検証を完了し、train 447,090行・723.507時間・327話者IDグループ、valid 12,951行・22.329時間・106グループを確定しました。[全量準備の記録](research/2026-10-07-gol-only-m2a-preparation.md)を参照してください。

**取得・前処理・アライメント・latent事前計算・監査・学習・評価はすべてVast.aiで行います。** 最終manifestと音声区間・分割間のPCM/IDグループ非重複、連結WAV全27,051本のハッシュを確認して学習を開始しました。ラベル分離と実声優の分離は区別します。既存8,000語彙tokenizerはGOL＋MoeSpeech由来ですが、今回の音声train/validにはMoeSpeechを混ぜていません。[最新計画](plans/2026-10-07-next-training-and-release.md)と[学習・保存点評価](research/2026-10-07-gol-only-m2a-training-results.md)を参照してください。

このデータでM2aを20kまで学習・機械評価し、現在は試聴所見待ちでGPUを停止しています。固定manifest、採否理由、データrevision・ハッシュ等の識別情報は回収済みですが、約1,004時間の生音声とlatentキャッシュは外部バックアップに含めていません。インスタンス削除後の再開には、同じrevisionからの再取得・前処理・整合性確認が必要です。重み・tokenizer・評価音声の回収と、学習用データのバックアップを区別します。

以下のコーパス全体の数値・利用条件は8月の調査記録です。学習・公開の対象revisionと利用条件は実行・公開前に確認し、当時の記録だけで現在の許可範囲を断定しません。

## MoeSpeechPlus (`ayousanz/moe-speech-plus`)

[litagin/moe-speech](https://huggingface.co/spaces/litagin/moe-speech-license) にアノテーションを追加したデータセットです。

### 実測値

| 項目 | 値 |
|---|---|
| 規模 | 473キャラクター / 395k ファイル / 約623時間 |
| 容量 | HF 上 151.6 GB（473個の zip）→ 展開後 約184 GB |
| 音声形式 | 44.1kHz 16bit mono WAV、1ファイル 2〜15秒 |
| 品質 | プロ声優のスタジオ収録、ノイズ・BGM なし、機械フィルタ済み |
| zip 単位 | **キャラクター1人 = zip 1個**（`uuid.uuid4().hex[:8]` の匿名 ID） |
| zip サイズ | 中央値 213 MB / 平均 321 MB / 最大 1,652 MB |

### 付加アノテーション

各音声と同じファイル名の json として格納されています。

| フィールド | 生成元 |
|---|---|
| `anime_whisper_transcription` | [litagin/anime-whisper](https://huggingface.co/litagin/anime-whisper) |
| `parakeet_jp_transcription` | [nvidia/parakeet-tdt_ctc-0.6b-ja](https://huggingface.co/nvidia/parakeet-tdt_ctc-0.6b-ja) |
| `duration` | — |
| `speechMOS` | UTMOS v2 (T05) |
| `DeBERTa_Sentiment` / `_Top_Label` / `_Top_Score` | microsoft/deberta-v3-large |
| `Audio_Emotion_Scores` / `_Top_Label` / `_Top_Score` | litagin/anime_speech_emotion_classification |
| `Qwen2_Emotion_Label` | Qwen/Qwen2-Audio-7B-Instruct |

### 強み

- **44.1 kHz** — Mimi の 24 kHz に対して帯域に余裕がある。音響品質の上限を決めるのはこちら。
- **話者ラベルがある** — キャラ別フォルダなので、同一話者のクリップを連結して擬似長尺ファイルを作れる。これは後述の [短尺クリップ問題](training-strategy.md) の解決に必須。
- **転写が2系統ある** — anime-whisper と parakeet の相互 CER を取れば、転写品質でフィルタできる。
- **部分ダウンロードが可能** — zip がキャラ単位なので、必要なキャラ数だけ取得できる。

| DL量 | キャラ数 | 音声時間 |
|---|---|---|
| 20 GB | 約120 | 約82h |
| **30 GB** | **約160** | **約123h** |
| 40 GB | 約190 | 約164h |

!!! warning "この表は無作為に取った場合です"
    上の数字は `--order random` に相当します。`prepare_moespeech.py` の既定は
    `--order largest`（`total_duration_min` の降順）で、その場合 **124時間に届くのは約28キャラ**
    です。zip の個数が 1/6 以下になり、DL も展開も速くなります。

    根拠は `info.csv`（12.5 KB、リポジトリのトップレベル）で、**473キャラ全ての `num_files` /
    `total_duration_min` / `f0_mean` を持っています**。音声を1バイトも落とさずに規模と選定を
    決められるので、`select_characters` はこのファイルしか読みません。

    引き換えに話者の多様性は落ちます。検証フェーズの目的は「パイプラインが正しいか」の
    切り分けであって話者数ではないのでこれを既定にしていますが、本番フェーズでは選定基準を
    変える前提です。

### 注意点

- **転写は ASR 自動生成のみ**。`training/README.md` は「音響は良いのに transcript に従わない場合は転写が不正確」「手動転写を優先せよ」と明記している。相互 CER + speechMOS でのフィルタが必要。当初は「20〜40% 落として実効 400〜500時間」と想定していたが、**実測は想定と違った**: 選定28話者・74,612クリップで speechMOS の中央値は**2.281**、相互 CER の中央値は **0.154**。`--min-mos 3.0` を切ると CER を一切見なくても124.4時間が16.2時間になる（[詳細](training-strategy.md)）。UTMOS は朗読音声で較正された尺度なので、キャラクター演技に絶対値の床を当てるのは指標とドメインのずれを測ることになる。採用した閾値は `--max-cer 0.2 --min-mos 0.0` で、**87.1時間（67%）**が残った。
- **ドメインが偏る** — アニメ／ギャルゲのキャラクター演技。ニュース読み上げのような中立トーンは苦手になる（README の「audiobook で学習すると本を読んでいるように聞こえる」の裏返し）。
- **感情ラベルに `Sexual1` / `Sexual2` が含まれる**。公開モデルにするなら該当クリップの除外を検討。
- `not-for-all-audiences` タグ付き。

### ライセンスと配布

!!! danger "再配布禁止 — サンプル音声を同梱してはいけない"
    このデータセットは**著作権法第30条の4（情報解析目的）でのみ使用が許可**されており、**再配布は禁止**されています。

    学習に使うこと自体は問題ありませんが、チェコ語モデルが `voices/` に ParCzech 話者の音声を同梱したのと**同じことをしてはいけません**（キャラクター音声の再配布に当たる）。日本語モデルを公開する際のサンプルボイスは、**自前または許諾済みの音声**を用意する必要があります。

## GOL (`midralab/gol-dataset`)

ビジュアルノベルの音声を作品単位でまとめた webdataset 形式のデータセット。
**2026-08-30 に `metadata.tsv`（1.68 GB）を取得して全件を実測しました。** 数値は README の
記載と完全に一致します（発話数・話者数・合計時間の3つとも）。

### 実測値

| 項目 | 値 |
|---|---|
| 規模 | **7,405,094 発話 / 19,349話者 / 10,654時間** |
| 容量 | 7,019 GB（607 tar）。**0.66 GB/時間** |
| 音声形式 | **48 kHz 32bit mono WAV**、平均 5.18秒 |
| 構成 | `<game_id>/<speaker>/<file>.wav` + `metadata.tsv` |
| DL 単位 | **`<game_id>.tar` = 1作品**（中央値 17.4時間・35話者） |
| 利用条件の8月記録 | README 空・タグなし。当時は権利関係を確認済みと記録。選定モデル・同梱音声の公開前に対象revisionと許諾範囲を再確認 |

### `metadata.tsv` の形式

音声を1バイトも落とさずに選定できる、MoeSpeech の `info.csv` と同じ役割のファイルです。

```
game_id	speaker	text	file_path	duration
00E16AD7…	151DBA2B…	そうだ！貴官のことも教えていただけませんか？	00E16AD7…/151DBA2B…/z1001#00622.wav	5.4092
```

**`file_path` が `<game_id>/<speaker>/` の形を破っている行は 7,405,094 行中 0 件**でした。
構造は完全に一貫しています。

### クリップ長の分布（1/7 サンプリング）

| min | p10 | p25 | **中央値** | p75 | p90 | max | 平均 |
|---|---|---|---|---|---|---|---|
| 0.30s | 1.48 | 2.68 | **4.55** | 7.00 | 9.61 | 57.04 | 5.18 |

MoeSpeech（中央値 5.46秒）より短く、**連結の必要性はこちらの方が高い**。

### 話者分布は極端に偏っています

| | |
|---|---|
| 1話者あたり時間の**中央値** | **0.6分** |
| 平均 / 最大 | 33分 / 53.9時間 |
| **1時間以上の話者** | **2,095人**（計 9,493時間 = 全体の89%） |
| 2時間以上 | 1,583人（8,764時間） |
| 発話が1つだけの話者 | 3,922人 |

**19,349という話者数を額面通りに受け取ってはいけません。** 実質使えるのは約2,000人で、
ただしその2,000人が音声の9割を持っています。話者単位の held-out も、この2,000人から取ります。

### tar を大きい順に取ったとき

| 目標時間 | 必要な tar | 話者数 | 容量（概算） |
|---|---|---|---|
| 124時間 | **2本** | 348人 | 約80 GB |
| 500時間 | 7本 | 1,161人 | 約330 GB |
| 1,000時間 | 18本 | 2,451人 | 約660 GB |
| **2,000時間** | **45本** | 4,768人 | 約1.3 TB |
| 5,000時間 | 154本 | 12,143人 | 約3.3 TB |

MoeSpeech の「zip = 1キャラ」より粗い単位（tar = 1作品・約35話者）ですが、
**時間あたりの取得効率は高い**です。

### 強み

- **量** — 10,654時間。単独で英語リファレンス2,000時間の5倍。
- **48 kHz** — Mimi の 24 kHz に対して余裕があり、MoeSpeech の 44.1 kHz より上。
- **話者ラベルがある** — `<game_id>/<speaker>/` で分かれており、MoeSpeech と同じ形で連結できる。
- **`metadata.tsv` を単独取得できる**（1.68 GB）。7 TB の音声を落とさずに選定が決まる。

### 注意点

- **転写は1系統のみ**。MoeSpeech では2系統の相互 CER が品質の代理指標でしたが、
  **GOL では同じ手が使えません。** 別の指標（speechMOS を自前で計算する、長さと文字数の比を見る等）
  を設計する必要があります。**これがフェーズ2で新しく設計すべき最大の項目です。**
- **容量が大きい**。0.66 GB/時間で、2,000時間なら 1.3 TB。インスタンスのディスクを
  これで見積もってください。
- 空テキストが 1,055 行あります（全体の 0.014%）。

!!! success "`。。。。。。` 問題は生データには在りません"
    `metadata.tsv` の `text` 列で「。。」を含む行は **612行（0.01%）**でした。
    2k サブセットで 44.6% が該当した問題は、**あのサブセットが持つ3列目（正規化テキスト）
    固有のもの**で、生データは影響を受けません。

### 前処理のコスト（8月の旧概算）

現在のM2aはGOLの生データを使い、21アーカイブ約656.69 GBを取得済みです。以下の旧320 GBサブセットを前提とした概算を、現行M2aの容量や取得時間として使わないでください。音声・latents・checkpointを含む現行の実測は[準備記録](research/2026-10-07-gol-only-m2a-preparation.md)、評価の時間費用は[保存点評価](research/2026-10-07-gol-only-m2a-training-results.md)に記載しています。

| 項目 | コスト |
|---|---|
| ダウンロード | 152 + 320 = **472 GB**。HF egress 無料、100 MB/s で約80分 |
| ディスク | 素のままだと約1 TB。**前処理は変換しません**（`concatenate()` は 44.1 kHz の wav をそのまま書き、リサンプルは dataloader が読み込み時に行う）ので、**ボリュームはこの形のまま持つ前提で見積もってください**。mp3/opus 化すれば 80〜150 GB に落とせますが、**それをする段はどこにも実装されていません**（下の tip の通り、自分で変換してマニフェストの `path` を差し替えるなら読み手は追随します） |
| CPU 前処理 | 展開・連結・マニフェスト化。**リサンプルはしません**（`concatenate()` は 44.1 kHz のまま書き、リサンプルは dataloader が読み込み時に行う）。**全て単一プロセス**で、実装が在る MoeSpeech 側の `prepare_moespeech.py` に並列化は入っていないので、コアを増やしても速くなりません。効くのはシングルコア性能とディスクのスループットだけです。実測は 124.4 時間ぶんで**合計34分**。アライメントは別で、GPU 2時間30分・CPU 89時間です |
| 強制アライメント | フェーズ1の実測から **約0.02 GPU-h/音声1時間**（RTX PRO 6000 で 85.5h を2.5h）。2,000h なら約48 GPU-h |

!!! tip "音声は mp3/opus に変換してよい"
    `training/dataloader.py` と `align_data.py` はマニフェストの `path` に対して `start` / `duration` で直接シークします（英語版が LibriVox の章まるごとの mp3 に窓を張っているのと同じ方式）。WAV のまま保持する必要はありません。
